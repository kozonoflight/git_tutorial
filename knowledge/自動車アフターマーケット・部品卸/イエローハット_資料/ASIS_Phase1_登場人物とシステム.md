# Phase1 AS-IS：登場人物・関連システム（確認用）

> 対象: **Phase1＝タイヤ・その他カー用品の卸受発注**の現状整理  
> 方針: 資料根拠＋**いま考えられる想定**を明示し、先方に「これで合っていますか？」と聞く  
> 凡例: 【資料】根拠あり　【想定】未確認の仮説　【確認】先方への質問

#### ★最重要確認（ユーザー指定）

> **タイヤ・その他カー用品の卸事業の管理者は、イエローハット様ですか？ ジョイフル様ですか？ あるいはどちらもですか？**  
> （例: 方針・看板＝YH／受注・仕入・請求の実務＝ジョイフル、など分担があれば教えてください）

【資料】メモ・PPTは「YH → ジョイフル → 取引先」の商流。看板で受注、とある。  
【想定】実務オペはジョイフル、対外的な顔はYH、の可能性が高いが**決めつけない**。

## 2. 関連システム（Phase1で名前が出るもの）

資料の「既存システム連携」＋卸オペで通常絡むもの。

| システム | Phase1での想定役割 | 確度 | 【確認】 |
|----------|-------------------|------|----------|
| **基幹（ERP／受発注・マスタ）** | 受注起票・売上・**商品マスタの正**？・掛率？ | 名前のみ【資料】 | 製品名は？ 商品マスタの正は基幹で合っているか |
| **倉庫管理（WMS）** | 自社倉庫の在庫・出荷指示 | 名前のみ | 製品名・拠点数。基幹との連携は自動／CSV／手か |
| **店舗POS** | 店舗の販売・入荷・店舗在庫 | 名前のみ | 卸用在庫とPOS在庫は別か同一か。基幹連携の有無 |
| **適合システム** | 車種・型式での適合（検索の裏）。**適合情報の正は基幹ではなく適合システム（別管理）** | 別管理＝確定（No.7で別掲） | 製品名。誰がメンテ。基幹商品とJAN等の紐付け方法 |
| **予約システム** | Phase1本丸ではないが連携列挙あり | Phase2寄り | Phase1時点では触らない想定でよいか |
| （ある？）**BtoC EC／サイト** | タイヤ検索の流用候補 | 発言のみ | 製品・画面。卸とは別システムか |
| （ある？）**Excel／共有フォルダ** | 掛率表・見積・原価計算 | 【想定】痛みから推測 | 属人ファイルの有無 |

## 3. 現状オペの想定フロー（Phase1）

すべて【想定】。合っているか確認する。

### 3.1 受注

```
取引先（ディーラー／整備工場／YH FC／中古車販売店？）
    │
    │  電話・FAX・メール
    ▼
受注担当（ジョイフル？ YH？）
    │
    │  【想定】内容確認・見積（必要時）・条件（掛率）参照
    │  【想定】基幹へ手入力で受注起票
    ▼
基幹
    │
    ├─【想定】自社在庫あり → 倉庫へ出荷指示（WMS or 基幹）
    └─【想定】なし／直送方針 → メーカー手配（直送 or 取寄せ※現状非対応の注記あり）
```

| # | 【想定】 | 【確認】一文 |
|---|---------|--------------|
| O1 | 受注チャネルは電話・FAX・メールが中心 | 比率は？ ほか（EDI・既存WEB）は？ |
| O2 | **受注を受けた担当者が基幹に手入力している** | **合っていますか？** 一部は別手段か |
| O3 | 見積は基幹外（Excel等）のこともある | 見積はどう作っているか |
| O4 | 取引先別掛率は担当者が知っている／表を見て適用 | 掛率マスタは基幹にあるか |

### 3.2 在庫

| # | 【想定】（複数仮説・決めつけない） | 【確認】 |
|---|----------------------------------|----------|
| I1 | **卸用の在庫**は倉庫（＋必要なら基幹）で見ている | 卸在庫の正は基幹？ WMS？ |
| I2 | **店舗在庫**は各店POSで持っている | POS在庫を卸受注の引当に使っているか／見せるだけか／使っていないか |
| I3 | 「店舗も含めたリアルタイム在庫」は**いまできておらず、やりたいこと**（モノタロウがベンチ） | 現状、担当者は倉庫在庫だけ見て受注しているか |
| I4 | 自社品とメーカー直送／取寄せが混在し、在庫の見え方がバラバラ | 欠品時の手順は？ |

【確認】**各商品の在庫は、いまどこで・どう管理していますか？**  
（基幹／WMS／POS／Excel のどれが正か。拠点単位か会社全体か）

### 3.3 仕入・入荷

ユーザー仮説をそのまま確認項目にする。

| # | 【想定】（ユーザー案を含む） | 【確認】 |
|---|------------------------------|----------|
| P1 | **店舗の店頭販売用**は、各店舗が仕入→POS入荷→（あれば）基幹連携、という流れがありうる | **仕入は各店舗で行い、店舗POSに入荷し、それが基幹に連携している、で合っていますか？** |
| P2 | **卸用（ジョイフル倉庫）**の仕入は、店舗とは別ルート（本部／ジョイフル一括仕入）の可能性が高い | 卸倉庫への仕入主体・発注システムは？ |
| P3 | メーカー直送は、倉庫を経由せず取引先へ届く | 直送時の仕入計上・在庫の持ち方は？ |
| P4 | 取寄せは「現状非対応」（設計書注記） | システム非対応の意味（受注しない／手運用のみ）は？ |

→ 店舗仕入と卸仕入を**同一視しない**。【想定】では二系統ありうる、と書く。

### 3.4 マスタ・価格

| # | 【想定】 | 【確認】 |
|---|---------|----------|
| M1 | **商品マスタの正は基幹** | **合っていますか？** POSや適合側にもマスタがある場合、どちらが正か |
| M2 | JAN・型番は基幹にあり、受注時に参照 | JANはどこがメンテか |
| M3 | 取引先別卸値（掛率・個別単価）は属人／Excel寄りで、基幹に完全には載っていない可能性 | 単価の正はどこか |
| M4 | **適合情報は適合システムが正（別管理・確定）**。基幹商品とJAN等で紐づけ | 紐づけ方法・メンテ担当（→ 確認質問と図解 Q3） |

## 5. 先方への確認リスト（Phase1・この回の本題）

そのまま質問してよい順。

### A. 登場人物・管理者

1. Phase1の取引先は **ディーラー／整備工場／YH FC加盟店／中古車販売店** で合っていますか？ ほかは？  
2. **タイヤ・その他カー用品の卸事業の管理者は、イエローハット様／ジョイフル様／どちらも、のどれですか？** 役割分担があれば教えてください。  
3. 受注担当・請求・契約名義は、それぞれどちらですか？

### B. 受注

4. 受注は電話・FAX・メールが中心、で合っていますか？（おおよその比率）  
5. **受注を受けた担当者が、基幹へ手入力している、という理解で合っていますか？**  
6. 見積はどのツールで作り、どう受注につなげていますか？

### C. 在庫・仕入・マスタ

7. **各商品の在庫は、いまどこで管理していますか？**（基幹／WMS／POS／その他。正はどれか）  
8. **仕入は各店舗で行い、店舗POSに入荷 → 基幹へ連携、という理解で合っていますか？**  
   （卸倉庫向け仕入が別にある場合は、その流れも教えてください）  
9. **商品マスタの正は基幹、で合っていますか？**  
10. 取引先別掛率・単価の正はどこにありますか？  
11. 自社出荷とメーカー直送の振分けは、誰が・何を見て決めていますか？  
12. 適合・WMS・POS・基幹の製品名（通称可）と、いま自動連携しているものはありますか？

## 6. 社内向けメモ

- ユーザー仮説（手入力・店舗仕入→POS→基幹・マスタ正＝基幹）は**もっともらしいが資料未記載** → すべて【想定】ラベルで確認する。  
- 「店舗仕入」だけに寄せると卸倉庫・メーカー直送が見えなくなるので、**卸用と店舗用を分けて聞く**。  
- 管理者（YH vs ジョイフル）が決まると、契約・請求・基幹オーナー・EC上の売り手が一気に定まる。**最初に潰す。**
