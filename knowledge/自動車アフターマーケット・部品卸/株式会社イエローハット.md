## 1. 何を求められているか（結論）

**一言**: イエローハット看板の卸（実務はジョイフル→取引先）を、電話／FAX中心から脱し、**タイヤ中心のBtoB受発注を自動化・一元化**したい。まずは**Phase1をシンプル・低予算・来春**。勝ち筋は**リアルタイム在庫・納期（モノタロウ級）＋適合検索＋見積→注文**。

| 求められているもの | 内容 |
|--------------------|------|
| **本命プロダクト** | BtoB受発注プラットフォーム（先方言では Web EDI／次世代BtoB） |
| **主商材** | **タイヤ**（工賃・付帯・セットとの組み合わせが前提） |
| **利用者** | 取引先＝ディーラー／整備工場／法人等（YH店舗網も在庫・作業の一端） |
| **Phase1で欲しい体験** | 掛率単価 → 適合検索 → 在庫・納期表示 →（見積）→ 注文 → 既存系と連携 |
| **先にやらなくてよい** | 作業送客の本格化、メーカー取寄せ連携、保管WMS、下取り査定（Phase2〜3） |
| **提案に期待されること** | 要件の優先度整理、Phase分割、来春に間に合う最小構成、既存（適合・基幹・WMS・POS・予約）連携方針 |

## 2. 商流・現状の痛み

```
イエローハット（看板・グループ）
    → 子会社 ジョイフル（卸・メーカーベンダー）
        → 取引先（ディーラー／整備工場／その他）
```

公開情報とも整合: 卸強化はジョイフルによる商品開発・新規取引先開拓、との記載あり。

### AS-ISの限界（先方設計書「3つの限界」）

1. **アナログ受発注** … 電話・FAX・メール → 転記ミス・誤配送・確認工数  
2. **仕入・物流が複雑** … 自社出荷とメーカー直送の混在、欠品時手配、**原価・粗利が手計算**  
3. **取引先別条件の属人化** … 個別掛率・決済・帳票がバックオフィス限界  

打合せ補足: イエローハットの看板で受注できている／店舗も含めた在庫を見たい／JAN・適合検索が重要。

---

## 3. 先方が描くコンセプト

- 自社・メーカー（仕入先）・取引先（店舗／法人／整備工場）と基幹を**共通DBでつなぎ**、  
  **受注 → 在庫引当 → 自動仕入中継 → 売上確定**まで人手を介さず双方向処理  
- BtoB取引先に優位な仕組みで**競合に負けないサービス**→新規開拓・事業拡大  
- タイヤは検索が複雑 → **BtoC機能の流用**を検討したい、との発言あり  

※コンセプトは大きく、**実装はPhase分割で小さく始める**意向（7/22: 1stはシンプルで）。

## 4. フェーズ分け（先方プラン）

| Phase | テーマ | 中身 |
|-------|--------|------|
| **1** | **受発注一元化** | タイヤ中心に受発注を自動化・一元管理。競合にない独自性も欲しいが、まずシンプル |
| **2** | 店舗への作業送客／即時配送 | ディーラー等のあぶれた交換・車検を仲介。当日配送・当日作業。メーカー取寄せ拡大 |
| **3** | リース・レンタカー／タイヤ保管 | 保管請負＋店舗連携の新規システム。下取り・買取（トレッド連携）もここ寄り |

### 5.4 タイヤ保管システム（Phase3・別プロダクト色が強い）

主要機能: 預かり登録・デジタル点検／棚ロケ（4本1SKU）／出庫ステータス可視化  
BtoB連携: 履き替え出庫×PIT予約API／残溝→新品松竹梅見積クロスセル／保管料の月次請求一本化  

※ご要件まとめPPTの保管フロー図に「TAS様で考えたタイヤ保管サービス」とあり。**保管の型は社内（TAS案件）の検討資産を流用した説明図**と解釈。YH要件そのものがTAS案件、ではない。

## 7. 提案・設計への示唆

| 論点 | 示唆 |
|------|------|
| スコープ | **Phase1 = タイヤBtoB受発注の最小構成**に切る。保管・下取り・作業送客はロードマップ提示に留める |
| Mustの核 | ①複数単価 ②在庫・納期（倉庫＋店舗）③適合／JAN検索 ④関連（工賃等）⑤見積→注文 ⑥配送2本1口 |
| 難所 | 既存適合DB・基幹・WMS・POS・予約との連携。取寄せ非対応の現状をどう扱うか |
| 差別化の見せ方 | Phase1でも「モノタロウ級の在庫・納期」「見積→注文」「インチ候補」で競合差を語れる |
| リスク | コンセプト（完全自動化・メーカー双方向）と来春・低予算が矛盾しやすい → **段階的自動化**を明示 |
| 類比 | TAS（ホイール適合・チャネルBtoB）、日東おまかせナビ（見積・専用提案）、チャネル（在庫・加工） |

### Phase1提案スコープ案（社内たたき）

**入れる**: 会員／取引先別単価、適合＋コード検索、倉庫・店舗在庫・LT、カート、見積PDF・承認・注文、工賃・セット、2本1口ルール、CSV大口、出荷日指定  
**連携は段階**: マスタ・在庫・受注の必須連携から。POS／予約は読み取りor後続  
**入れない（明示）**: 保管WMS、下取り査定、作業送客本丸、メーカー取寄せ自動、当日配送のフル自動

## 8. 一言サマリ（上司・社内共有用）

セールスサイト経由の**社長特命**案件。YH看板の卸（ジョイフル経由）をデジタル化し、**タイヤBtoBで在庫・納期・適合・見積注文**まで通したい。先方資料は壮大（保管・作業送客まで）だが、現場は**Phase1シンプル・来春・低予算**。提案は欲求の全量を並べず、**必須7＋タイヤ特有をPhase1に圧縮し、2/3はロードマップ**で応える形がよい。
